# План разработки Iskan

Поэтапный план от MVP до полной системы. Оценки в человеко-неделях (ч-нед) даны для ориентира и предполагают небольшую команду (см. §«Команда»). Сроки — при параллельной работе потоков (агент / бэкенд / фронтенд).

## Принципы

- **Вертикальные срезы**: каждая фаза даёт работающую end-to-end функцию, а не «слой».
- **Приватность и право с самого начала**: уведомление, ретеншн, аудит закладываются в MVP, а не «потом».
- **Сначала данные, потом красота**: сбор и хранение → отчёты → живой просмотр → AI.

## Фаза 0. Фундамент и инфраструктура — ~3 ч-нед

Цель: скелет, на который встают остальные фазы.

- Репозиторий, монорепо-структура (`agent/`, `server/`, `web/`, `ai/`, `deploy/`), CI.
- Docker Compose со всеми базовыми сервисами (Postgres+Timescale, Redis, MinIO, RabbitMQ, Traefik).
- Каркас API (.NET), миграции БД, базовая схема (organizations, employees, devices, users, roles).
- Аутентификация пользователей + RBAC (заготовка ролей).
- Механизм **enrollment** агента (одноразовый токен → mTLS-сертификат → `agent_id`).

**Результат:** сервер поднимается одной командой; агент может зарегистрироваться.

## Фаза 1. MVP-агент и приём телеметрии — ~5 ч-нед

Цель: увидеть базовую активность в дашборде.

- Агент: Windows-служба + session helper, сбор активного окна/процесса, активность/простой.
- Локальный буфер (SQLite), батч-отправка, устойчивость к оффлайну.
- Ingestion Service: приём событий, запись в TimescaleDB, свёртка в интервалы.
- MSI-пакет с тихой установкой (`/qn SERVER=... ENROLL_TOKEN=...`).
- Дашборд: список сотрудников/устройств, онлайн-статус, таймлайн приложений за день.

**Результат:** установили агент → видим, кто в каких приложениях и сколько времени.

## Фаза 2. Скриншоты и продуктивность — ~4 ч-нед

- Агент: периодические скриншоты (downscale, WebP, throttle), выгрузка в MinIO через сервер.
- URL активной вкладки (расширение браузера / UI Automation).
- Справочник категорий приложений/доменов + правила сопоставления.
- Расчёт продуктивности, агрегаты (день/неделя/отдел), базовые отчёты и галерея скриншотов.
- Настройки приватности: интервал, размытие/исключения приложений, отключение по политике.

**Результат:** отчёты «продуктивное/непродуктивное время» + просмотр скриншотов.

## Фаза 3. HR-модуль и штрафы — ~4 ч-нед

- Графики работы, смены; расчёт присутствия и опозданий.
- Отпуска/больничные/отгулы: заявки, статусы, прикрепление документов, календарь отсутствий.
- Движок правил штрафов (условие → формула суммы), генерация нарушений.
- Согласование нарушений руководителем, отчёт по удержаниям, экспорт.

**Результат:** учёт отсутствий и автоматический расчёт штрафов с согласованием.

## Фаза 4. Живой просмотр экрана — ~4 ч-нед

- Командный канал агент↔сервер (постоянный WebSocket).
- Захват экрана через Desktop Duplication, WebRTC-стрим.
- Signaling-сервис + развёртывание coturn (TURN/STUN).
- Просмотр в браузере админа, presence «онлайн/можно подключиться».
- Строгий RBAC на функцию + аудит каждой сессии просмотра.

**Результат:** админ по кнопке подключается к экрану сотрудника в реальном времени.

## Фаза 5. AI-анализ скриншотов — ~4 ч-нед

- AI Worker (Python): OCR (PaddleOCR/Tesseract) + vision-модель.
- Конвейер: скриншот → семплинг/дедуп → OCR → VLM-классификация → метки/флаги нарушений.
- Поддержка облачных (Claude/GPT-4o vision) и локальных (Qwen2-VL/LLaVA) моделей — переключаемо.
- Контроль стоимости: семплинг, кэш, батчинг; отображение AI-оценок в отчётах.
- Подробности — [AI_ANALYSIS.md](AI_ANALYSIS.md).

**Результат:** система сама оценивает, чем реально занят сотрудник, и подсвечивает нарушения.

## Фаза 6. Закалка, масштаб, эксплуатация — ~4 ч-нед

- Авто-обновление агента, tamper-resistance, watchdog.
- Ретеншн-политики, шифрование медиа, полный аудит и экспорт.
- Нагрузочное тестирование (цель — 500+ агентов), оптимизация ingestion и агрегатов.
- Мониторинг сервера (Prometheus/Grafana), алерты, бэкапы.
- Документация администратора, скрипты массовой раскатки (GPO/Intune/SCCM), Helm-чарт (опц.).

**Результат:** промышленно пригодная версия, готовая к внедрению.

## Сводная оценка

| Фаза | Содержание | Оценка |
|------|-----------|--------|
| 0 | Фундамент и инфраструктура | ~3 ч-нед |
| 1 | Агент + телеметрия (MVP) | ~5 ч-нед |
| 2 | Скриншоты + продуктивность | ~4 ч-нед |
| 3 | HR + штрафы | ~4 ч-нед |
| 4 | Живой просмотр | ~4 ч-нед |
| 5 | AI-анализ | ~4 ч-нед |
| 6 | Закалка и масштаб | ~4 ч-нед |
| | **Итого** | **~28 ч-нед** |

При команде из 3–4 человек с параллельными потоками — ориентировочно **3–4 месяца** до полной версии; **MVP (фазы 0–2) — ~6–8 недель**.

## Команда

- **Windows-разработчик (C#/.NET)** — агент, служба, захват экрана, MSI.
- **Backend-разработчик (.NET)** — API, ingestion, HR/правила, signaling.
- **Frontend-разработчик (React)** — дашборд, отчёты, живой просмотр, HR-UI.
- **ML-инженер (Python, part-time)** — AI-конвейер (подключается к фазе 5, консультирует раньше).
- **DevOps (part-time)** — Compose/K8s, TURN, мониторинг, раскатка.

## Риски и меры

| Риск | Мера |
|------|------|
| **Правовые/приватность** | Уведомление сотрудников, согласие, ретеншн, аудит — с MVP (см. COMPLIANCE.md) |
| Антивирусы помечают агент | Подпись кода (code signing), заявка вендорам на whitelisting, прозрачное поведение |
| Session 0 / многосессийность (RDP, смена юзера) | Раннее разделение service/helper, тесты на терминальных серверах |
| Живой просмотр за NAT | TURN-сервер, ранние сетевые тесты |
| Стоимость AI на большом объёме | Семплинг, локальные модели, OCR-предфильтр |
| Объём скриншотов/трафик | Downscale, throttle, ретеншн, компрессия |
| Нагрузка ingestion при росте | Stateless-сервисы, очередь, Timescale-компрессия, нагрузочные тесты (фаза 6) |

## Что уточнить у заказчика перед стартом

- Юрисдикция и порядок оформления мониторинга (уведомление/согласие, положение о контроле).
- Масштаб (число ПК сейчас и в перспективе) и модель хостинга (on-prem / облако).
- AI: облачные модели допустимы или строго локальные (из-за конфиденциальности скриншотов)?
- Нужна ли запись видео или достаточно периодических скриншотов.
- Глубина сбора: только метаданные активности или также содержимое (кейлоггинг) — с учётом закона.
