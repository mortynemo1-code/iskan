# Руководство администратора

## Подготовка и запуск

Минимально: Ubuntu 22.04/24.04, Docker Engine 26+, Compose v2, 8 vCPU, 32 ГБ RAM. Для 100 сотрудников и medium-видео на 7 дней рекомендуется 2 ТБ и 100 Мбит/с входящего канала.

Запуск: `WORKFORCE_TLS_NAME=<FQDN> ./install.sh`. Настройте DNS и firewall: 80/443 TCP, 8189 UDP; 8554 TCP разрешайте только для RTSP fallback в доверенной сети.

## Первый вход

1. Сохраните сгенерированный bootstrap-пароль.
2. Войдите как `admin`, подключите TOTP.
3. Удалите `BOOTSTRAP_ADMIN_PASSWORD` из `.env` и перезапустите API.
4. Создайте отделы, сотрудников, графики, пользователей и скоупы.
5. Назначьте сотрудника новому устройству и подтвердите его.

## Настройки

- «Параметры сбора»: idle, снимки, допуск к графику, медиаплеер, размытие, приватные маски и юридический контакт.
- «Внешний вид»: стандартная, контрастная, deuteranopia и тёмная схемы; пороги применяются без перезагрузки.
- «Хранение»: ретеншен событий, снимков и видео глобально/по отделу/сотруднику.
- «Правила»: меньшее число — выше приоритет. Используйте тест на 7 дней и пересчёт 30 дней с прогрессом.
- «Агенты»: логи, обновление, перезапуск, Windows-account mapping и карантин.

## Обновления

Соберите и подпишите MSI корпоративным code-signing сертификатом. Загрузите его в «Канареечные обновления», задайте 5%, включите релиз, затем повышайте до 100. Агент проверяет SHA-256 и Authenticode, устанавливает в окне обслуживания.

## Мониторинг и восстановление

`make monitoring` запускает Grafana `:3000`, Prometheus `:9090` и Loki. Контролируйте online/offline, ingest, live, диск, ошибки отчётов и очередь команд.

`make backup` создаёт PostgreSQL custom dump и Redis archive. Восстановление на отдельном стенде:

```bash
WORKFORCE_CONFIRM_RESTORE=YES ./scripts/restore.sh backups/postgres-YYYYMMDD.dump
```

Проверяйте `/api/v1/ready`, `docker compose ps`, `docker compose logs --tail=200 api worker mediamtx`. Диагностические архивы доступны только администраторам.

## Данные сотрудника

В карточке есть «Выгрузить данные» и «Удалить данные». Удаление требует ввода UUID, физически удаляет объекты/события, отвязывает устройства и сохраняет append-only аудит.

## Видео

В «Параметрах сбора» задаются режим `off/on_demand/always_on/scheduled/trigger`, профиль, окна расписания, задержка триггера и автостоп просмотра. Сервер дополнительно запрещает запуск вне назначенной смены, в праздник, на перерыве и при lock. Worker индексирует fMP4 в БД и MinIO; закреплённые диапазоны исключаются из ретеншена.

`STORAGE_HIGH_WATERMARK_PERCENT` (по умолчанию 85) включает аварийную очистку: самые старые незакреплённые видеосегменты удаляются из локального playback-хранилища и MinIO до возврата ниже порога; администраторы получают уведомление, операция попадает в аудит и Prometheus.
