# Пилотная проверка агента

Поставить агента на одну машину, убедиться, что данные доходят до сервера, и посмотреть на них глазами руководителя. Рассчитано на один рабочий день.

Адрес системы в локальной сети: `https://192.168.88.121`

---

## Шаг 0. Подготовить справочники — до установки

> **Без этого тест остановится на полпути.** Сейчас в системе нет ни одного отдела и ни одного сотрудника. Подтвердить устройство можно только привязав его к сотруднику: в админке это выпадающий список, и он будет пустым.

Войдите как `admin` (потребуется код TOTP) и создайте минимум по одной записи:

1. **Админка → Отделы** — создайте отдел, например «Тест».
2. **Админка → Сотрудники** — создайте сотрудника, на чью машину ставите агента. Статус должен быть «активен», иначе он не появится в списке при подтверждении устройства.

Заодно проверьте **Админка → Графики**: если у сотрудника нет назначенного графика, часть проверок — опоздания, работа вне смены, запрет видео вне графика — просто не сработает.

## Часть 1. Установка на машину сотрудника

### 1.1. Проверить связь с сервером

Выполнить **на машине сотрудника**, PowerShell:

```powershell
Test-NetConnection 192.168.88.121 -Port 443
```

`TcpTestSucceeded : True` — можно продолжать.

`False` — машина не видит сервер. Дальше идти бессмысленно: агент установится, но будет молча копить события в локальной очереди и никуда их не отправлять. Сначала сеть.

### 1.2. Установить пакет

PowerShell **от имени администратора**:

```powershell
msiexec /i Workforce.Agent.Installer.msi /qn /norestart TOKEN="<installation-token>" SERVER="https://192.168.88.121"
```

Токен смотрится на сервере — это общий секрет для всех агентов, обращайтесь с ним как с паролем:

```bash
grep INSTALLATION_TOKEN ~/iskan/.env
```

Пакет сейчас не подписан, поэтому Windows покажет предупреждение SmartScreen. Для пилота это допустимо; для массовой раскатки через GPO или Intune подпись обязательна.

### 1.3. Разрешить самоподписанный сертификат

Сертификат сервера выписан на `94.41.21.238`, а обращаться агент будет на `192.168.88.121` — имена не совпадут, и соединение оборвётся. Агент умеет доверять сертификату по отпечатку:

```powershell
setx /m Agent__ServerCertificateSha256 "B7F1A716F7E590AB80F5DE6517938D207CAD217A187E90758B9E1398E40458A5"
```

```powershell
Restart-Service WorkforceMonitoringAgent
```

Перезапуск обязателен: переменная читается только при старте службы.

При замене сертификата отпечаток изменится и агенты перестанут подключаться. Правильное решение на будущее — выпустить сертификат на то имя, по которому обращаются агенты.

### 1.4. Что увидит сотрудник

Система видимая, скрытой работы не предполагает:

- иконка в трее появляется сразу и не убирается;
- при первом запуске показывается уведомление «Ознакомлен»;
- в окне агента — статус, длительность сессии, версия, состояние связи, контакт и сроки хранения;
- кнопка «Личное время» прекращает снимки и видео, фиксируется только состояние `BREAK`;
- при live-просмотре появляется неотключаемое уведомление.

Что система **не** записывает: введённый текст, коды клавиш, буфер обмена, файлы, переписку, микрофон и веб-камеру. Считается только количество нажатий и кликов, без содержания.

## Часть 2. Подтвердить устройство

Устройство регистрируется само, но до подтверждения не считается online и не попадает в отчёты.

**Админка → Новые устройства** → у появившейся записи выбрать сотрудника из списка → **Подтвердить**.

Если запись не появилась — переходите к разделу «Если что-то не работает».

## Часть 3. Как смотреть за сотрудником

### Мониторинг

Основной экран наблюдения. Разделяет две разные вещи:

- **зелёная точка** — есть связь с агентом (heartbeat);
- **статус** — что происходит: работа, простой, блокировка экрана, перерыв.

Ниже — таймлайн на Canvas: день или неделя, зум колесом мыши, перетаскивание, всплывающие подсказки по отрезкам. Клик по имени открывает карточку сотрудника.

### Дашборд

Сводка: кто online, продуктивность, отсутствия, сигналы. Отсюда же переход в карточку сотрудника с KPI, приложениями, таймлайном и дисциплиной.

### Скриншоты

Фильтруются, открываются в лайтбоксе, выгружаются архивом при наличии права. Каждый просмотр и выгрузка попадают в аудит — это важно знать: смотреть чужие снимки анонимно не получится.

### Live

Запускается только для online-сотрудника, вне перерыва и блокировки и внутри разрешённого графика. До 16 потоков мозаикой. Сотрудник всегда видит индикатор трансляции.

В архиве выбираются дата и интервал, можно вырезать MP4-фрагмент и закрепить его, чтобы не удалился по ретеншену.

### Отчёты

Продуктивность, табель, отделы, приложения и сайты, дисциплина, отсутствия, день, аномалии. Выгрузка в CSV, XLSX и PDF, сохранение пресетов и рассылка по расписанию.

## Часть 4. Если что-то не работает

Почти всё видно в логе агента на машине сотрудника:

```powershell
Get-Content C:\ProgramData\WorkforceMonitoring\logs\agent-*.log -Tail 50
```

| Симптом | Причина |
| --- | --- |
| Ошибка TLS в логе | не задан или неверен отпечаток сертификата — вернитесь к шагу 1.3 |
| Таймауты подключения | нет сети до сервера — шаг 1.1 |
| `403 Invalid installation token` | неверный токен |
| Служба стартует и падает | смотрите Event Viewer, обычно не хватает прав |
| Служба работает, иконки в трее нет | проблема запуска Session Agent в сессии пользователя, смотрите лог |

Состояние службы:

```powershell
Get-Service WorkforceMonitoringAgent
```

### Проверки на стороне сервера

Устройство дошло до сервера:

```bash
docker exec iskan-postgres-1 psql -U workforce -d workforce -c "SELECT hostname, agent_version, is_approved, last_seen FROM devices ORDER BY created_at DESC LIMIT 5;"
```

Строка есть — регистрация прошла. `is_approved = f` означает, что устройство ещё не подтверждено.

События идут:

```bash
docker exec iskan-postgres-1 psql -U workforce -d workforce -c "SELECT count(*), max(ts_start) FROM activity_events;"
```

Счётчик растёт — цепочка работает целиком.

Состояние сервиса:

```bash
cd ~/iskan && docker compose -f compose.yaml -f compose.production.yaml ps
```

## Что останется сделать после пилота

- **Подписать MSI** корпоративным сертификатом — без этого GPO и Intune откажутся его ставить.
- **Выпустить TLS-сертификат** на реальное имя сервера вместо самоподписанного, чтобы не раздавать отпечаток на каждую машину.
- **Решить вопрос доступа** — сейчас наружу проброшен только SSH, агенты работают лишь внутри локальной сети.
